# Цифровой помощник студента в MAX

Мини-приложение в мессенджере MAX и платформа для вузов и работодателей: расписание, практики и заявки, диагностика профессиональных навыков с проверкой практического задания, шаблоны документов и обращения. Сотрудники вуза ведут заявки и обращения, работодатель подбирает кандидатов по подтверждённым навыкам.

## Основной сценарий

1. Студент открывает приложение из чата с ботом — вход выполняется по подписанным данным запуска MAX, без пароля.
2. На главной видит текущую пару, статус заявки на практику и ближайший срок приёма заявок.
3. Проходит диагностику навыков: вопросы с автосохранением ответов, затем практическое задание.
4. Специалист организации проверяет практическое задание по рубрике — уровни навыков и предварительный грейд пересчитываются.
5. Студент выбирает практику, видит совпадение своих навыков с требованиями и подаёт заявку, решая, показывать ли результаты диагностики.
6. Координатор вуза принимает решение по заявке; студент получает уведомление от бота.
7. Работодатель отбирает кандидатов по навыкам и отмечает интерес; следующий шаг делает координатор.
8. Из любого раздела студент отправляет обращение с сохранённым контекстом, получает решение и подтверждает его.

## Запуск

Нужен Docker с плагином Compose. Одна команда поднимает приложение, очередь, планировщик и PostgreSQL:

```bash
docker compose up -d --build
```

Приложение открывается на http://localhost:8088 (`/app/start`, `/admin`, `/docs/api`). По умолчанию стек запускается в демонстрационном режиме: загружаются демо-данные и работает кнопка демо-входа, `.env` для этого не нужен.

Остановка без потери данных и повторный запуск:

```bash
docker compose down
```

```bash
docker compose up -d
```

Полный сброс вместе с базой и загруженными файлами:

```bash
docker compose down -v
```

### Порты и компоненты

| Компонент | Порт | Назначение |
|---|---|---|
| `app` | `${APP_PORT:-8088}` → 80 | FrankenPHP: мини-приложение, админ-панель, API, вебхук бота |
| `queue` | — | Обработчик очереди: уведомления бота, обработка событий |
| `scheduler` | — | Планировщик Laravel |
| `db` | внутренний 5432 | PostgreSQL 17, данные в томе `pgdata` |

Файлы шаблонов документов лежат в томе `storage`.

### Переменные окружения

Полный список с комментариями — в [.env.example](.env.example). Для рабочего сервера скопируйте его в `.env` и задайте:

| Переменная | Значение |
|---|---|
| `APP_ENV`, `APP_DEBUG` | `production` и `false` (на демонстрационном стенде — `demo`, чтобы работала кнопка демо-входа) |
| `APP_KEY` | Пусто — сгенерируется при первом запуске и сохранится в томе |
| `APP_URL` | Внешний адрес, например `https://max-hack.ai-weblab.ru` |
| `APP_PORT` | Порт публикации; на сервере за nginx — `127.0.0.1:8090` |
| `DB_PASSWORD` | Свой пароль **до первого запуска** |
| `MAX_BOT_TOKEN`, `MAX_BOT_NAME` | Токен бота и его username без «@» |
| `MAX_WEBHOOK_SECRET` | Секрет вебхука, приходит в заголовке `X-Max-Bot-Api-Secret` |
| `SEED_DEMO`, `MINIAPP_DEMO_LOGIN` | `0` и `false` для рабочего пилота |
| `SESSION_SAME_SITE`, `SESSION_SECURE_COOKIE`, `SESSION_PARTITIONED_COOKIE` | `none`, `true`, `true` при работе по HTTPS — нужно, если веб-версия MAX открывает приложение во встроенном окне |

Секреты в репозиторий не добавляются: `.env` в `.gitignore`, в `.env.example` только примеры.

## Интеграция с MAX

- **Мини-приложение.** В настройках бота указывается `https://<домен>/app/start`. Страница получает `window.WebApp.initData`, сервер проверяет подпись токеном бота ([документация MAX](https://dev.max.ru/docs/webapps/validation)) и создаёт сессию. Данные старше часа отклоняются.
- **Бот.** Вебхук `https://<домен>/max/webhook`, только HTTPS на порту 443 с сертификатом доверенного центра или Минцифры. Запросы проверяются по секрету, обработка уходит в очередь, ответ отдаётся сразу.
- **Уведомления.** Решение по заявке, ответ на обращение, проверка практического задания. Сбой отправки не отменяет действие сотрудника.
- **Сертификат Минцифры** лежит в `platform/docker/certs/` и добавляется в доверенные внутри образа: без него запросы к `platform-api2.max.ru` не проходят проверку TLS.

Подписка на события и проверка токена:

```bash
docker compose exec app php artisan max:webhook show
```

```bash
docker compose exec app php artisan max:webhook subscribe
```

При `SEED_DEMO=1` и пустой базе загружаются вымышленные организации, люди и контент; в интерфейсе стоит бейдж «Демо-данные». Пароль всех учётных записей — `password`, они предназначены только для проверки.

В наборе: учебная группа с расписанием на неделю, 4 частых вопроса, шаблон документа, 3 предложения практики, тест из 8 вопросов с практическим заданием, пройденная и проверенная попытка, заявки и обращения в разных состояниях.

## Ограничения текущей версии

- Расписание, частые вопросы и предложения практик заполняются в админ-панели или сидером; автоматического импорта из систем вуза нет.
- Управленческая аналитика и кабинет работодателя с самостоятельной публикацией вакансий не реализованы.
- Прохождение диагностики не контролируется наблюдателем: результат отмечается как предварительный.
- Уровни «Прикладной» и «Уверенный» и грейд «Junior» присваиваются только после проверки практического задания человеком.
- Тестовые и демонстрационные данные обозначены явно и не выдаются за реальные.
