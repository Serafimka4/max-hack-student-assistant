Проблема

Практику ищут вслепую,
а вуз узнаёт о проблемах последним

Студент

Предложения практик рассыпаны по чатам и объявлениям. Непонятно, каким требованиям он соответствует и что происходит с поданной заявкой.

Координатор

Узнаёт о студенте без места и о проблемах на практике в последний момент. Заявки и договорённости живут в переписке и таблицах.

Работодатель

Получает отклики без подтверждённых навыков: резюме студента без опыта мало что говорит, отбор идёт вручную.

Что за этим стоит

Повседневные сервисы — расписание, справки, шаблоны — тоже разбросаны, поэтому студент снова идёт в деканат, а сотрудники отвечают на одни и те же вопросы. Это гипотеза, которую мы проверяем интервью и пилотом, а не выдаём за факт.

Главное отличие

Мы не обещаем «ИИ-оценку кандидата». Навыки подтверждаются проверяемыми заданиями, практическую часть оценивает человек по рубрике, а решение принимают люди: координатор и работодатель. Всё, что не проверено, так и называется — «не оценено».

Ключевая механика

Диагностика навыков, которой можно верить

Как считается

  • Вопрос засчитывается только при полном совпадении ответа — частичных баллов нет.
  • Балл по навыку — полученные баллы к максимуму по вопросам этого навыка.
  • Меньше минимума вопросов по навыку — «недостаточно данных», а не низкая оценка.
  • Пороги и минимумы хранятся в версии теста и согласуются до отбора.

Почему это честно

  • Прикладной и уверенный уровни и грейд «Junior» — только после проверки практики человеком.
  • Практика повышает уровень лишь там, где базовый подтверждён вопросами.
  • Прохождение без наблюдателя отмечено как предварительный результат.
  • Опубликованная версия теста неизменяема: правка создаёт новую версию.
  • Студент может один раз запросить пересмотр оценки.

Кабинеты организаций

Вуз, работодатель, проверяющий

Вуз

  • Каталог практик с требованиями к навыкам
  • Заявки: рассмотрение, решение, история, причина отказа
  • Обращения: в работу, решение, повторное открытие
  • Шаблоны документов с версиями файлов
  • Частые вопросы и статистика «помогло / не помогло»

Работодатель

  • Отклики только на свои предложения
  • Фильтры по навыку, уровню и наличию проверенной практики
  • Карточка: что подтверждено, что ниже требуемого, что не оценено
  • Отметка «Заинтересован» — следующий шаг делает координатор

Проверяющий

  • Очередь решений с счётчиком непроверенных
  • Баллы по критериям рубрики и комментарий студенту
  • Имя студента скрыто — только номер попытки
  • Своё решение проверять нельзя, история сохраняется

Доступ определяется типом организации и ролью участника: администратор, координатор, редактор, проверяющий. Работодатель видит результаты только тех студентов, которые разрешили их показать при подаче заявки.

Платформа MAX

Что использовано и зачем

Мини-приложение

MAX Bridge передаёт данные запуска, сервер проверяет подпись токеном бота по алгоритму из документации и создаёт сессию. Данные старше часа отклоняются.

Кнопка «Назад» в шапке MAX, скачивание файлов через WebApp.downloadFile по временной подписанной ссылке.

Бот

Вебхук с проверкой заголовка X-Max-Bot-Api-Secret, ответ сразу, обработка в очереди. Уведомления: решение по заявке, ответ на обращение, проверка практики.

Диплинки ?startapp= открывают конкретный экран: расписание, карьеру, помощь, карточку практики, результат диагностики.

POST /messages?user_id=… → уведомление с кнопкой в мини-приложение POST /subscriptions → подписка на bot_started, message_created https://max.ru/<бот>?startapp=offer_7 → открыть карточку практики сразу после входа

Отдельно решены две вещи, о которые обычно спотыкаются: сертификат Минцифры добавлен в доверенные внутри образа (иначе запросы к API MAX не проходят), а cookie сессии выставлены как SameSite=None; Secure; Partitioned — для веб-версии MAX, где приложение открывается во встроенном окне.

Интеграции

API: вуз подключается данными, а не кодом

Что открыто

  • /v1/auth/max — вход по данным запуска MAX
  • /v1/organizations/{вуз}/document-templates — шаблоны и версии файлов
  • /v1/organizations/{орг}/assessments — тесты, версии, публикация
  • /v1/organizations/{орг}/skills — справочник навыков
  • /v1/me, /v1/organizations — профиль и организации

Как устроено

  • Токены Sanctum: для интеграции и для мини-приложения
  • Документация OpenAPI 3.1 собирается из кода, не пишется руками
  • Чужая запись — 404, нехватка прав — 403, нарушение правила — 422 с текстом
  • Лимиты: 120 запросов в минуту, 20 на вход через MAX
  • DATA-API.yaml: 19 проверок и 7 ролей с ожидаемыми ответами

Важное решение

Мини-приложение и админ-панель не ходят в собственное API по HTTP: все три интерфейса вызывают один слой действий и прав. Поэтому правила совпадают, а API не отстаёт от интерфейса — каждый сценарий покрыт тестом.

Честно о границах

Что не сделано и что дальше

Ограничения текущей версии

  • Расписание и контент заполняются в админ-панели: автоматического импорта из систем вуза нет
  • Управленческая аналитика не реализована — показатели считаются по сохранённым событиям, но экрана пока нет
  • Работодатель не публикует предложения сам: их заводит вуз
  • Прокторинга нет, результат диагностики предварительный
  • Пилот с реальным вузом не проводился: данные демонстрационные и помечены

Ближайшие шаги

  • Аналитика: студенты без места, заявки без ответа, обращения без решения — с периодом и размером выборки
  • Импорт расписания из CSV с проверкой ошибок при загрузке
  • Второе направление диагностики и расширенная рубрика
  • Пилот на одном факультете: интервью, согласование данных и владельцев процессов

Мы намеренно не добавляли генеративные функции в основной путь: сценарий работает без LLM, а значит его можно проверить и повторить.
