# Сценарий демонстрации и ручной проверки

Стенд: https://max-hack.ai-weblab.ru. Пароль всех учётных записей админ-панели — `password`. Данные вымышлены и помечены бейджем «Демо-данные».

Полный путь занимает 6–8 минут. Каждый шаг описан вместе с ожидаемым результатом.

## 1. Студент открывает приложение

Открыть https://max-hack.ai-weblab.ru/app/start и нажать «Войти как демо-студент». В MAX тот же экран открывается кнопкой бота `@t475_hakaton_max_bot`, вход выполняется по подписанным данным запуска без пароля.

Ожидается: главный экран с приветствием, текущей или ближайшей парой, статусом заявки на практику и ближайшим сроком приёма заявок.

## 2. Расписание

Вкладка «Расписание».

Ожидается: неделя с пометкой «числитель» или «знаменатель», текущая пара выделена, показаны источник расписания и время обновления. Кнопка «Сообщить об ошибке» у пары открывает форму с уже заполненным контекстом.

## 3. Диагностика навыков

«Карьера» → «Мои навыки». У демо-студента уже есть проверенная попытка: HTML/CSS и HTTP — «Прикладной», JavaScript и Git не подтверждены, грейд «Начальный».

Чтобы показать прохождение: открыть тест → «Пройти заново» → ответить на несколько вопросов → «Завершить досрочно».

Ожидается: вопросы по одному экрану, ответ сохраняется сразу, работает таймер. На экране результата — уровень и процент по каждому навыку, версия и дата теста, пометка «Практика не проверялась», список «Что подтянуть».

## 4. Практическое задание

На экране результата отправить решение: ссылка `https://example.com/demo` или описание.

Затем войти в админ-панель как `reviewer@demo.test` → «Проверка практики» → открыть попытку → выставить баллы по критериям → сохранить.

Ожидается: проверяющий видит номер попытки без имени студента; после сохранения уровни пересчитываются, у студента на экране результата появляются баллы по критериям и комментарий. Практика повышает уровень только там, где базовый подтверждён вопросами.

## 5. Заявка на практику

У студента: «Карьера» → «Практики» → «Frontend-стажёр». Видно сравнение требований с подтверждёнными навыками. Включить «Приложить результаты диагностики» и подать заявку.

Ожидается: сообщение об успешной подаче, статус «Подана». Повторное нажатие не создаёт вторую заявку.

## 6. Решение координатора

Админ-панель, `coordinator@demo.test` → «Заявки». Найти заявку, нажать «Взять на рассмотрение», затем «Принять» или «Отказать» с причиной.

Ожидается: статус меняется, в истории видно кто и когда, отказ без причины не проходит. У студента в разделе «Заявки» появляется решение и комментарий; если у него есть учётная запись MAX, бот присылает уведомление.

## 7. Работодатель подбирает кандидата

Админ-панель, `hr@demo.test` → «Кандидаты».

Ожидается: только отклики на предложения этого работодателя и только от студентов, разрешивших показать результаты. Работают фильтры по навыку и уровню. В карточке — что подтверждено, что ниже требуемого, что не оценено, версия и дата теста, статус практики. Кнопка «Заинтересован» передаёт следующий шаг координатору: приглашение оформляет человек.

## 8. Обращение и его решение

У студента: в расписании нажать «Сообщить об ошибке», описать проблему, отправить.

Ожидается: в форме показан контекст (пара и группа) и предупреждение, что обращение конфиденциальное, но не анонимное.

Координатор в админ-панели: «Обращения» → «В работу» → «Решено» с описанием решения.

Ожидается: студент видит решение в разделе «Помощь» и может подтвердить его; при наличии учётной записи MAX приходит уведомление.

## 9. Ежедневные сервисы

Вкладка «Помощь»: поиск по частым вопросам, оценки «Помогло» и «Нужна помощь», скачивание шаблона документа.

Ожидается: ответ «Нужна помощь» открывает форму обращения с сохранённым вопросом; файл скачивается по временной ссылке (в MAX — через `WebApp.downloadFile`).

## 10. API

Открыть https://max-hack.ai-weblab.ru/docs/api — интерактивная документация, собранная из кода. Примеры запросов и проверки: [API.md](API.md) и [../DATA-API.yaml](../DATA-API.yaml).

## Что показать отдельно

- **Честность оценки.** «Не оценено» — отсутствие данных, а не низкий результат. Прикладной уровень и грейд «Junior» невозможны без проверки практики человеком. Прохождение без наблюдателя отмечено как предварительное.
- **Разграничение доступа.** Работодатель видит только разрешённые результаты; проверяющий не видит имени; правильные ответы не покидают сервер; обращения конфиденциальны.
- **Переносимость на другой вуз.** Всё содержимое привязано к организации: новый вуз — это данные и настройки, а не переписывание сценария.
